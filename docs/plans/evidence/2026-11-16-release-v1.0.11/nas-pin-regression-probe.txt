# OPS-21 在 NAS 生产上仍会触发的实测探针（零风险：临时目录，非部署目录）

日期：2026-11-16
对象：GHCR 上真实的已发布边车镜像 ghcr.io/ly1713/platform-api-updater:v1.0.11
目的：确认已发布的 v1.0.11 边车是否包含 OPS-21 的属主修复。

## 1. 已发布镜像内是否含修复

$ docker run --rm --entrypoint sh ghcr.io/ly1713/platform-api-updater:v1.0.11 \
    -c 'grep -c keep_owner /srv/app/updater/versionstate.py'
0

即：v1.0.11 边车镜像里的 versionstate.py 是修复前版本。
原因：修复提交 839bf6f 在 v1.0.11 tag（68dcb9a）之后，未被任何已发布镜像包含。

## 2. 按 NAS 当前真实挂载方式执行 pin（复现）

NAS 上边车实际挂载：
  bind /vol1/1000/docker/platform-api/src -> /compose rw=true
  User= (空 = root)

探针（临时目录 /tmp/ops21-probe，模拟生产 .env 属主/权限，跑完即删）：

$ printf "PLATFORM_VERSION=v1.0.11\nPLATFORM_PORT=9100\n" > /tmp/ops21-probe/.env
$ chown 1000:1001 /tmp/ops21-probe/.env; chmod 755 /tmp/ops21-probe/.env
$ docker run --rm -v /tmp/ops21-probe:/compose --entrypoint python \
    ghcr.io/ly1713/platform-api-updater:v1.0.11 \
    -c 'from app.updater import versionstate; versionstate.write_pinned_version("/compose/.env", "v1.0.12"); print("pin done")'
pin done

写入前  owner=ztb:Users uid=1000 gid=1001 mode=755
写入后  owner=root:root uid=0 gid=0 mode=600
内容：  cat: /tmp/ops21-probe/.env: Permission denied   （宿主用户 ztb 读取失败）

## 结论

当前 NAS 生产实例（v1.0.11）上，任何一次网页一键升级走到 pin 步骤，
都会把 /vol1/1000/docker/platform-api/src/.env 变成 root:root / 600，
此后宿主用户（ztb, uid=1000）的 docker compose 操作全部 permission denied。

修复已存在于代码（839bf6f），但必须随下一个版本发布才能在生产生效。
